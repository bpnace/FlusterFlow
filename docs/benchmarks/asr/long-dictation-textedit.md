# Long dictation in TextEdit

Measure on the same Mac with the same locally synthesized audio file, output and input devices, model, language, and TextEdit document setup for both builds. Warm the installed model before playback. Start with an empty disposable plain-text document and play the fixture over the speakers into the microphone. Use a fixture long enough to cross multiple decode boundaries.

Record the monotonic time at the stop signal and after Accessibility confirms the text change. Compare that interval across baseline and candidate runs. Read back the inserted text and compare it to the known synthetic reference. Report deletions, insertions, substitutions, and repeated adjacent words. Mark an unconfirmed insertion as a failed run.

A candidate must reduce the median stop-to-confirmed-insertion time and introduce no additional word errors or repetitions. If separate acoustic runs disagree, compare both decode paths on the same captured audio. Keep individual run counts and timings alongside the median. The test uses local models and synthetic material.

The benchmark starts and stops the production capture and Whisper Turbo recognizer directly. It uses FlusterFlow's Accessibility insertion and verifies the resulting value in TextEdit. The stop signal is generated by the test at the end of playback. This isolates capture finalization, recognition and insertion from the global shortcut and text cleanup.

On an Apple Silicon Mac with microphone and Accessibility permission and the installed Turbo model:

```sh
mkdir -p .build/benchmark
say -v Anna -r 165 -f docs/benchmarks/asr/long-dictation-reference-de.txt \
  -o .build/benchmark/reference.aiff
swift build --build-system native --disable-automatic-resolution --build-tests
FLUSTERFLOW_RUN_LONG_DICTATION_TEXTEDIT=1 \
FLUSTERFLOW_ACOUSTIC_SMOKE_AUDIO="$PWD/.build/benchmark/reference.aiff" \
FLUSTERFLOW_WHISPER_SMOKE_REFERENCE="$(cat docs/benchmarks/asr/long-dictation-reference-de.txt)" \
xcrun xctest -XCTest \
  WhisperFlowTests.LongDictationTextEditTests/testLongSyntheticDictationIntoTextEditWhenExplicitlyRequested \
  .build/arm64-apple-macosx/debug/WhisperFlowPackageTests.xctest
```

Save the generated AIFF once and use the same file for both builds. The test prints the `FLUSTERFLOW_LONG_TEXTEDIT` metrics without printing transcript text.

## M5 results

The same 43.07-second, 118-word recording was played from the MacBook Pro speakers and captured by its built-in microphone. The AIFF SHA-256 was `0813456076713deddd565c4333d10625025fddbf72168d933c2a9ea2faed824a`.

| Build | Stop to confirmed insertion | Words | Missing | Extra | Substitutions | Adjacent duplicates |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Baseline 1 | 4,948 ms | 118 | 0 | 0 | 0 | 0 |
| Baseline 2 | 5,000 ms | 118 | 0 | 0 | 0 | 0 |
| Candidate 1 | 2,686 ms | 118 | 0 | 0 | 1 | 0 |
| Candidate 2 | 2,611 ms | 118 | 0 | 0 | 1 | 0 |

Median fell from 4,974 ms to 2,648.5 ms, a reduction of 2,325.5 ms (46.8%). Both candidate runs reused one of three Whisper chunks.

The two candidate runs each contained one substitution. Two further runs used `FLUSTERFLOW_LONG_TEXTEDIT_COMPARE_BATCH=1` to decode the exact same captured samples a second time with the full decoder. The paired transcripts had identical word sequences in both runs. One pair had zero substitutions and the other had one in both paths. No run had missing words, extra words, or adjacent duplicates.
