# Product

## Register

product

## Users

FlusterFlow is for a privacy-conscious Mac owner who dictates frequently in German and English while working across native, browser, and Electron text fields. The user expects a fast menu-bar workflow, clear local processing boundaries, recoverable recordings, and standard macOS behavior without needing to understand the underlying speech models.

## Product Purpose

FlusterFlow turns microphone input into conservative, locally processed text and inserts it at the current cursor position. It keeps recordings and transcript versions locally so failed or alternative transcriptions can be recovered without recording again. Success means the user can understand readiness, start dictation, recover a recording, and change configuration from one coherent app surface while the transient Flow Bar preserves focus in the target application.

## Brand Personality

Calm, precise, trustworthy. The interface should feel like a carefully made native macOS utility: quiet while everything works, explicit when a decision has privacy or data consequences, and never conversational or theatrical.

## Anti-references

- No fragmented collection of utility windows for closely related tasks.
- No web-dashboard shell, card grid, glassmorphism, neon AI styling, or decorative metric panels.
- No generic AI sparkles, anthropomorphic assistant language, or copied competitor geometry.
- No hidden local/cloud boundary, automatic model download, or vague privacy promise.

## Design Principles

1. One app, one place: overview, recordings, and configuration belong to one navigable window.
2. Preserve the writing flow: dictation remains a menu-bar and nonactivating Flow Bar interaction; the main window opens only for setup, recovery, or configuration.
3. Local is the baseline: name processing and storage consequences before implementation details.
4. Recovery over disappearance: failed work remains visible, understandable, and retryable.
5. Native restraint: familiar macOS navigation, controls, keyboard behavior, and accessibility semantics outrank visual novelty.

## Accessibility & Inclusion

Target macOS Human Interface Guidelines and WCAG 2.2 AA for essential text and controls. Support keyboard traversal, visible system focus, VoiceOver labels, Increase Contrast, Reduce Transparency, and Reduce Motion. Never communicate state through color alone, and allow longer German labels and explanatory privacy text to wrap without hiding actions.
